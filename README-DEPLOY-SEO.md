## Important SEO note about "meta keywords"
Google does not use the old <meta name="keywords"> tag for ranking. For that reason it has NOT been stuffed into this build.
Target phrases are instead included naturally in titles, headings, body copy, internal links and dedicated pages.

## Deploy to GitHub Pages
1. Open the GitHub repository that currently publishes:
   https://kavindanipun.github.io/salary-hourly-calculator/
2. Back up the current repository first.
3. Replace the existing site files with the contents of this ZIP.
4. Keep the same repository name/path so the existing public URL does not change.
5. Commit and push to the branch used by GitHub Pages.
6. Wait for GitHub Pages to finish deployment.
7. Open the public URL in an incognito/private window and test the calculator and all three guide pages.

## Google Search Console after deployment
1. Open URL Inspection.
2. Inspect:
   https://kavindanipun.github.io/salary-hourly-calculator/
3. Run "Test live URL".
4. If the page is available to Google, use "Request indexing".
5. In Search Console → Sitemaps, submit:
   https://kavindanipun.github.io/salary-hourly-calculator/sitemap.xml
6. Inspect each guide URL once after deployment:
   https://kavindanipun.github.io/salary-hourly-calculator/salary-to-hourly-australia/
   https://kavindanipun.github.io/salary-hourly-calculator/hourly-to-salary-australia/
   https://kavindanipun.github.io/salary-hourly-calculator/salary-conversion-table-australia/
7. Watch Performance → Queries and Pages for 2–4 weeks.
8. Do not keep changing titles every day. Let Google recrawl and collect data.

## GitHub Pages robots.txt caveat
A robots.txt file is only authoritative at the HOST root, for example:
https://kavindanipun.github.io/robots.txt

Because this project is published under a subdirectory, the included:
https://kavindanipun.github.io/salary-hourly-calculator/robots.txt
is useful as a project copy/reference but is not a substitute for a host-root robots.txt.
This does NOT block indexing: GitHub Pages is crawlable by default. Submit the sitemap directly in Search Console.

## Do NOT add
- noindex
- a canonical pointing to another domain/page
- JavaScript-only hidden main content
- dozens of near-duplicate keyword pages
- fake reviews/ratings in schema
- fake "updated today" dates
- repeated keyword blocks

## Ranking reality
This build improves technical indexability, relevance, crawlability and page quality, but no code can guarantee a Google ranking.
To move from impressions to stronger rankings, keep the site stable, get legitimate relevant links/mentions, add genuinely useful content based on Search Console queries, and improve pages from real user data.
